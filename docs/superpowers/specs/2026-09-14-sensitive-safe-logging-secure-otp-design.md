# 민감정보 안전 로깅 및 안전한 OTP 생성 설계

## 배경

현재 서버는 모든 요청 본문과 응답 본문을 전역 `console.log`로 출력한다. 이 방식은 전화번호, 비밀번호, OTP, 토큰처럼 운영 로그에 남아서는 안 되는 값을 노출할 수 있다.

한편 운영 장애를 분석하려면 어떤 요청이 실행됐고 성공 또는 실패했는지 확인할 수 있어야 한다. 따라서 로깅 자체를 없애지 않고, 전역 로그에는 요청을 식별하고 성능과 결과를 판단하는 메타데이터만 남긴다. 구체적인 업무 실패는 해당 서비스가 안전하다고 판단한 필드만 별도로 기록한다.

OTP는 현재 `Math.random()`으로 생성한다. 인증에 사용하는 값이므로 Node.js 표준 암호학적 난수 생성기로 교체한다.

## 목표

- 요청 및 응답 본문을 운영 로그에 기록하지 않는다.
- 요청 종류, 결과, 처리 시간을 확인할 수 있는 전역 로그를 유지한다.
- GraphQL 요청은 `operationName`으로 구분한다.
- 외부 서비스 실패 시 필요한 업무 문맥을 마스킹하여 기록한다.
- OTP를 암호학적으로 안전한 6자리 숫자로 생성한다.
- 기존 GraphQL 및 SMS 호출 계약을 유지한다.

## 제외 범위

- 범용 재귀형 body redactor
- 로깅 라이브러리 또는 OTP 라이브러리 추가
- 요청 ID 생성과 분산 추적 시스템 도입
- 로그 저장소, 접근 제어, 보존 기간 정책 구성
- 아직 존재하지 않는 이메일 발송 기능 구현
- OTP 저장, 만료, 재전송 제한 및 검증 API 구현

## 설계

### 1. 전역 요청 결과 로그

기존 응답 로깅 인터셉터를 전역 메타데이터 로거로 변경한다. 성공과 실패 모두 한 건의 구조화된 로그를 남긴다.

로그 필드는 다음으로 제한한다.

- `method`: HTTP 메서드
- `path`: 요청 경로
- `operationName`: GraphQL operation 이름, 이름이 없으면 `anonymous`
- `statusCode`: 성공 응답 또는 예외에 대응하는 상태 코드
- `durationMs`: 인터셉터 진입부터 완료까지 걸린 시간
- `outcome`: `success` 또는 `error`
- `error`: 실패한 경우에만 예외 클래스 이름

GraphQL `operationName`은 요청 body의 문자열을 직접 기록하지 않는다. Nest의 `GqlExecutionContext`가 제공하는 파싱된 `GraphQLResolveInfo`에서 읽는다. 따라서 GraphQL 이름 규칙을 통과한 값만 로그에 들어간다.

오류 메시지는 사용자 입력이나 외부 제공자의 응답을 포함할 수 있으므로 전역 로그에 기록하지 않는다. 요청 body와 응답 데이터도 성공 여부와 관계없이 기록하지 않는다.

### 2. 요청 body 로깅 제거

현재 `LoggerMiddleware`는 `req.body` 전체를 `console.log`로 출력하는 기능만 수행한다. 안전한 일부 필드만 구분할 업무 문맥이 없는 전역 계층이므로 애플리케이션 등록과 구현 파일을 제거한다.

전역 계층에서 범용 키 차단 목록을 사용하지 않는다. 차단 목록은 새 필드나 예상하지 못한 중첩 구조를 놓칠 수 있어 민감정보 비노출을 보장하지 못하기 때문이다.

### 3. 실패 지점의 업무 로그

정확한 입력값이 필요한 진단 정보는 각 업무 서비스가 안전한 필드만 선택해 기록한다. 이번 범위에서는 이미 존재하는 SMS 발송 실패 지점에 적용한다.

SMS 실패 로그는 다음 값만 포함한다.

- `event`: `sms.send.failed`
- `receiver`: 앞 3자리와 뒤 4자리만 남긴 전화번호
- `error`: 예외 클래스 이름

예를 들어 `01012345678`은 `010****5678`로 기록한다. 마스킹하기에 너무 짧은 값은 `[REDACTED]`로 대체한다. SMS 본문, OTP, 전체 전화번호, Aligo 인증정보, 외부 제공자의 오류 메시지는 기록하지 않는다. 로그를 남긴 뒤 기존 오류를 그대로 다시 던져 호출자의 동작을 바꾸지 않는다.

향후 이메일 발송 기능이 추가되면 같은 원칙을 해당 서비스 실패 경계에 적용한다. 예를 들어 템플릿 ID와 마스킹한 수신자만 기록하며, 전체 이메일 본문을 전역 로거에 추가하지 않는다.

### 4. OTP 생성

`UtilService.getOtp()`의 반환 타입과 호출 방식은 유지한다. 내부 구현만 Node.js 표준 `crypto.randomInt(100000, 1000000)`로 교체한다.

최솟값은 포함되고 최댓값은 제외되므로 가능한 결과는 `100000`부터 `999999`까지이며, 문자열 변환 후 항상 숫자 6자리가 된다. 새 의존성은 필요하지 않다.

## 데이터 흐름

### 성공 요청

1. 요청이 GraphQL 실행 계층에 들어온다.
2. 전역 인터셉터가 시작 시간을 기록한다.
3. resolver와 service가 요청을 처리한다.
4. 인터셉터가 응답 body를 읽지 않고 메서드, 경로, 파싱된 operation 이름, 상태 코드, 처리 시간과 `success`를 기록한다.
5. 기존 응답은 변경 없이 클라이언트로 전달된다.

### 실패 요청

1. 업무 서비스가 외부 호출 실패를 감지한다.
2. 해당 서비스가 허용된 마스킹 업무 문맥만 기록한다.
3. 서비스는 원래 오류를 다시 던진다.
4. 전역 인터셉터는 요청/응답 body와 오류 메시지 없이 메타데이터, `error`, 예외 클래스 이름을 기록한다.
5. 기존 Nest 예외 처리 흐름이 응답을 생성한다.

## 변경 대상

- `src/responseLogger.interceptor.ts`: GraphQL-aware 메타데이터 로깅
- `src/app.module.ts`: request body 로깅 미들웨어 등록 제거
- `src/logger.middleware.ts`: 삭제
- `src/common/sms.service.ts`: 실패 시 마스킹된 업무 문맥 기록
- `src/common/util.service.ts`: `crypto.randomInt()` 기반 OTP 생성
- 관련 unit 및 E2E 테스트: 민감정보 비노출, 실패 로그, OTP 난수 소스 검증

기존 파일 구조를 유지하며 범용 로깅 계층, redaction 유틸리티 또는 별도 OTP 클래스를 만들지 않는다.

## 오류 처리

- 인터셉터는 성공 결과나 오류를 소비하거나 변환하지 않는다.
- 실패 로그에는 예외 메시지와 stack을 넣지 않는다.
- SMS 서비스는 안전한 로그를 남긴 뒤 동일한 오류 객체를 다시 던진다.
- 이름 없는 GraphQL 요청은 실패시키지 않고 `anonymous`로 기록한다.
- 전화번호가 정상적인 길이가 아니어도 로그 처리 때문에 원래 실패가 가려지지 않도록 `[REDACTED]`를 사용한다.

## 테스트 전략

### 인터셉터 단위 테스트

- 이름 있는 GraphQL 요청이 메타데이터만 기록하는지 검증한다.
- 이름 없는 GraphQL 요청이 `anonymous`로 기록되는지 검증한다.
- 성공 응답 body의 토큰과 요청 body의 비밀번호가 로그에 포함되지 않는지 검증한다.
- 실패 시 예외 클래스 이름은 기록하지만 예외 메시지는 기록하지 않는지 검증한다.

### 애플리케이션 E2E 테스트

- 민감한 임의 필드가 포함된 실제 GraphQL 요청을 전송한다.
- 전역 콘솔 출력에 해당 값이 나타나지 않는지 검증한다.
- 기존 `healthCheck` 응답이 유지되는지 검증한다.

### SMS 서비스 단위 테스트

- 외부 호출 실패 시 마스킹한 전화번호가 기록되는지 검증한다.
- 전체 전화번호, OTP와 외부 오류 메시지가 기록되지 않는지 검증한다.
- 원래 오류가 호출자에게 다시 전달되는지 검증한다.
- 기존 성공 요청 payload가 바뀌지 않는지 기존 테스트로 확인한다.

### OTP 단위 테스트

- `randomInt(100000, 1000000)`을 호출하는지 검증한다.
- 반환값이 기존 계약대로 문자열인지 검증한다.

### 최종 검증

- 전체 unit test
- 전체 E2E test
- TypeScript build
- 민감한 본문을 출력하는 `console.log`, `req.body`, 응답 직렬화 패턴 검색
- `graphify update .` 실행

## 완료 조건

- 요청 및 응답 body가 전역 로그에 포함되지 않는다.
- GraphQL 요청 로그에서 operation 이름, 결과, 상태 코드와 처리 시간을 확인할 수 있다.
- SMS 실패 로그만으로 실패 이벤트와 마스킹된 수신자를 식별할 수 있다.
- OTP가 Node.js 암호학적 난수 생성기로 만들어진 6자리 문자열이다.
- 기존 SMS 성공 동작과 GraphQL health check가 유지된다.
- 새 런타임 의존성이 추가되지 않는다.
