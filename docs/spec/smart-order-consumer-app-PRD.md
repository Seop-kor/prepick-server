# Smart Order Consumer App PRD

- 문서 버전: v1.2
- 문서 목적: 모바일 스마트오더 Consumer App의 제품 요구사항 정의
- 대상: Consumer App + Consumer App에서 사용하는 Backend API
- 관리자/매장주 페이지: 본 PRD 범위에서 제외
- 실제 결제 연동: 본 PRD 범위에서 제외

---

## 1. 제품 개요

### 1.1 제품 목표

사용자가 현재 위치를 기준으로 주변 매장을 탐색하고, 원하는 매장의 메뉴를 선택하여 장바구니와 주문서를 거쳐 주문할 수 있는 모바일 스마트오더 앱을 제공한다.

서비스의 핵심 경험은 다음과 같다.

```text
앱 실행
→ 로그인 상태 확인
→ 미로그인 시 로그인
→ 주변 매장 탐색 또는 검색
→ 매장 상세 확인
→ 메뉴 선택
→ 하위 상품 선택
→ 장바구니
→ 주문서
→ 주문 완료
→ 주문 내역 확인
```

### 1.2 프로젝트 목적

이 프로젝트는 이직 포트폴리오를 목적으로 제작하는 스마트오더 Consumer App이다.

패스오더와 유사하게 사용자가 앱에서 주변 매장을 발견하고, 메뉴를 탐색하고, 매장에 방문하기 전에 주문할 수 있는 경험을 제공하는 것을 목표로 한다.

### 1.3 핵심 서비스 정책

- 매장과 메뉴를 포함한 서비스 탐색 기능은 로그인한 사용자만 이용할 수 있다.
- 로그인하지 않은 사용자는 로그인 및 회원가입 화면만 이용할 수 있다.
- 회원가입과 로그인은 이메일이 아닌 휴대폰 번호를 기준으로 한다.
- 하나의 휴대폰 번호는 하나의 회원 계정에만 사용할 수 있다.
- 회원가입 전 휴대폰 번호 인증이 필요하다.
- 휴대폰 인증번호는 숫자 6자리로 구성한다.
- 하나의 장바구니에는 한 매장의 상품만 담을 수 있다.
- 실제 결제 기능은 이번 범위에서 제외하지만 결제 확인 화면은 제공한다.


### 주요 기능

- 휴대폰 번호 입력
- 비밀번호 입력
- 로그인
- 회원가입 화면 이동

---

## 4.2 회원가입 화면

### 가입 기준

회원의 유니크한 가입 기준은 휴대폰 번호이다.

동일한 휴대폰 번호로 여러 계정을 만들 수 없다.

### 회원가입 흐름

```text
이름 입력
→ 휴대폰 번호 입력
→ 인증번호 전송
→ 6자리 OTP 입력
→ 인증 완료
→ 비밀번호 입력
→ 회원가입 완료
```

### UI 구성

```text
회원가입

이름
[홍길동                  ]

휴대폰 번호
[010-0000-0000       ] [인증번호 받기]

인증번호
[ _  _  _  _  _  _ ]

[인증하기]

비밀번호
[••••••••              ]

비밀번호 확인
[••••••••              ]

[회원가입]
```

### OTP 정책

- OTP는 숫자 6자리이다.
- 인증번호가 정상적으로 확인되어야 회원가입할 수 있다.
- 휴대폰 번호가 변경되면 다시 인증해야 한다.
- 이미 가입되어 있는 휴대폰 번호로는 회원가입할 수 없다.
- 인증번호 재전송 기능을 제공한다.

# 4.3 홈

홈은 단순한 주변 매장 리스트가 아니라 사용자가 주문할 매장을 발견하는 **탐색 중심 화면**으로 구성한다.

패스오더와 유사하게 여러 유형의 매장을 섹션별로 보여준다.

### 화면 구조

```text
안녕하세요 👋
강남구 역삼동에서
주문할 매장을 찾아볼까요?

[ 🔍 매장이나 메뉴를 검색해보세요 ]

┌──────────────────────┐
│   프로모션 / 이벤트 배너   │
└──────────────────────┘

가까운 매장                         전체보기 >
[매장 카드]
[매장 카드]
[매장 카드]

새로 들어왔어요                     전체보기 >
[매장 카드] [매장 카드]
```

### 상단 위치 영역

현재 사용자의 위치를 표시한다.

예:

```text
강남구 역삼동 ▼
```

위치 정보 사용이 불가능한 경우에도 검색을 통해 매장을 탐색할 수 있어야 한다.

### 검색

검색창 Placeholder:

```text
매장이나 메뉴를 검색해보세요
```

검색 대상:

- 매장명
- 메뉴명

### 프로모션 배너

홈 상단에는 프로모션 또는 서비스 안내 배너를 노출한다.

예:

```text
첫 주문을 시작해보세요!
주변 인기 카페를 빠르게 주문할 수 있어요.
```

### 가까운 매장

현재 위치 기준 가까운 매장을 리스트 형태로 보여준다.

### 신규 매장

최근 서비스에 등록된 매장을 보여준다.

# 4.4 매장 카드

매장 카드에는 다음 정보를 표시한다.

- 매장 이미지
- 매장명
- 카테고리
- 현재 위치와의 거리
- 영업 여부

예:

```text
┌──────────────────────┐
│      매장 이미지          │
├──────────────────────┤
│ 브루랩 강남점             │
│ 카페 · 350m              │
│ 영업 중                    │
└──────────────────────┘
```

매장 카드를 누르면 매장 상세 화면으로 이동한다.

# 4.6 매장 상세

### 상단

```text

```

### 메뉴 영역

카테고리를 가로 스크롤 형태로 제공한다.

```text

```

선택한 카테고리에 해당하는 메뉴를 아래에 표시한다.

### 메뉴 카드

```text
[메뉴 이미지]

아메리카노
고소한 원두로 만든 아메리카노
4,000원~
```

품절 메뉴는 `품절` 상태를 표시하고 선택할 수 없도록 한다.

# 4.7 메뉴 상세

하나의 메뉴 안에서 실제 주문할 하위 상품을 선택할 수 있다.

예를 들어 `아메리카노`라는 메뉴 안에 다음 상품이 존재할 수 있다.

```text
HOT 아메리카노
ICE 아메리카노
```

### UI 예시

```text
[아메리카노 이미지]

아메리카노
고소하고 깊은 풍미의 커피입니다.

온도를 선택해주세요.

○ HOT        3,500원
● ICE        4,000원

수량
[-]  1  [+]

총 4,000원

[장바구니 담기]
```

### 주요 기능

- 하위 상품 선택
- 수량 변경
- 선택한 상품의 가격 확인
- 장바구니 담기

# 4.8 장바구니

### UI 예시

```text
브루랩 강남점

아메리카노
ICE
4,000원
[-] 2 [+]

4,500원
[-] 1 [+]

[12,500원 주문하기]
```

### 주요 기능

- 상품 수량 증가
- 상품 수량 감소
- 상품 삭제
- 전체 주문 예상 금액 확인
- 주문서 이동

### 다른 매장 상품을 담는 경우

기존 장바구니에 A 매장의 상품이 있는데 B 매장의 상품을 담으려고 하면 확인창을 표시한다.

```text
다른 매장의 메뉴가 장바구니에 담겨 있습니다.

기존 메뉴를 비우고
새 매장의 메뉴를 담을까요?

[취소] [새로 담기]
```

```text
→ 주문 상세
```

# 6. 프론트엔드 화면/기능 범위

프론트엔드에서는 다음 사용자 화면과 인터랙션이 필요하다.

| 영역 | 주요 화면/기능 |
|---|---|
| 인증 | 로그인, 회원가입, OTP 인증 |
| 홈 | 위치, 검색, 프로모션, 가까운 매장, 신규 매장 |
| 검색 | 매장/메뉴 검색 결과 |
| 매장 | 매장 상세, 메뉴 카테고리, 메뉴 목록 |
| 메뉴 | 메뉴 상세, 하위 상품 선택, 수량 선택 |
| 장바구니 | 상품 확인, 수량 변경, 삭제, 주문 금액 확인 |
| 주문 | 주문서, 요청사항, 주문 완료 |
| 주문내역 | 진행 중 주문, 지난 주문, 주문 상세 |
| 더보기 | 회원 정보, 로그아웃 |

각 화면에서는 데이터가 없는 경우나 정보를 불러오지 못한 경우 사용자에게 이해할 수 있는 안내 화면을 제공한다.

예:

```text
주변에 주문 가능한 매장이 없습니다.
```

```text
검색 결과가 없습니다.
```

```text
장바구니가 비어 있습니다.
```

```text
주문 내역이 없습니다.
```

# 8. 필요한 API 목록

API의 세부 Request/Response 형식과 구현 방식은 별도 설계 단계에서 정의한다.

## 8.1 인증

```text
POST /auth/otp/request
```

휴대폰 번호로 회원가입 인증번호를 요청한다.

```text
POST /auth/otp/verify
```

사용자가 입력한 6자리 인증번호를 확인한다.

```text
POST /auth/signup
```

회원가입한다.

```text
POST /auth/login
```

휴대폰 번호와 비밀번호로 로그인한다.

```text
POST /auth/logout
```

로그아웃한다.

```text
GET /users/me
```

현재 로그인한 회원 정보를 조회한다.

---

## 8.2 홈 / 매장

```text
GET /stores
```

주변 매장 또는 검색 조건에 맞는 매장 목록을 조회한다.

```text
GET /stores/new
```

신규 매장을 조회한다.

```text
GET /stores/:storeId
```

매장 상세 정보를 조회한다.

```text
GET /search
```

매장명 또는 메뉴명으로 통합 검색한다.

프로모션 배너를 서버에서 관리할 경우 다음 API를 사용할 수 있다.

```text
GET /promotions
```

---

## 8.3 메뉴

```text
GET /stores/:storeId/menus
```

매장에서 판매하는 메뉴와 카테고리를 조회한다.

```text
GET /menus/:menuId
```

메뉴 상세와 주문 가능한 하위 상품을 조회한다.

---

## 8.4 주문

```text
POST /orders
```

장바구니의 상품으로 주문을 생성한다.

```text
GET /orders
```

현재 사용자의 주문 목록을 조회한다.

```text
GET /orders/:orderId
```

주문 상세를 조회한다.

# 9. 핵심 사용자 시나리오

이 앱에서 가장 중요한 시나리오는 다음과 같다.

```text
앱 실행
↓
로그인 상태 확인
↓
미로그인 시 로그인
↓
현재 위치의 주변 매장 확인
↓
원하는 매장 선택
↓
매장 메뉴 확인
↓
아메리카노 선택
↓
ICE 선택
↓
장바구니 담기
↓
다른 메뉴 추가
↓
장바구니 확인
↓
주문하기
↓
주문서 확인
↓
주문 완료
↓
주문내역에서 주문 확인
```

회원이 아닌 사용자는 다음 흐름을 통해 가입할 수 있다.

```text
회원가입
↓
휴대폰 번호 입력
↓
6자리 OTP 인증
↓
비밀번호 설정
↓
가입 완료
↓
로그인
↓
서비스 이용
```
